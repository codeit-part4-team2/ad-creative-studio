# 러시아워 무표정 AI 코믹 쇼츠 설계

- 작성일: 2026-08-11
- 적용 저장소: `ad-creative-studio`
- 적용 브랜치: `codex/rush-hour-shorts-design`
- 상태: 사용자 승인 설계
- 대체 대상: 기존 음악·자막 중심 러시아워 쇼츠 렌더링

## 1. 결정 요약

러시아워 쇼츠는 일반 광고와 분리된 소상공인 선택 기능이다. 사용자가 러시아워
쇼츠를 선택하면 별도 스타일 선택 없이 **무표정 AI 코믹형**을 기본이자 유일한
렌더링 스타일로 사용한다.

이 스타일은 고급 상품 이미지 3~4장, 정확한 한국어 발음, 명백히 인공적인 독특한
음색, 문장 사이의 의도적인 정적, 정돈된 동기화 자막을 결합한다. 배경음악과 효과음,
기존의 검은 자막 박스, 음악·자막 전용 대체 경로는 제거한다.

코미디는 오발음이나 어색한 단어가 아니라 다음 대비에서 만든다.

1. 화면과 자막은 고급 광고처럼 진지하게 구성한다.
2. 음성은 정확하게 발음하지만 무표정하고 명백히 인공적인 음색을 사용한다.
3. 영상당 한 번만 AI가 자신을 인식하는 짧은 코미디 비트를 구성한다.
4. 영상은 농담을 설명하거나 별도 효과를 넣지 않고 정상적인 CTA로 끝낸다.

## 2. 목표와 비목표

### 2.1 목표

- 10~15초, 1080×1920, H.264/AAC 러시아워 쇼츠를 생성한다.
- 같은 상품을 보존한 고품질 이미지 3~4장을 장면별로 사용한다.
- 상품명, 브랜드명, 숫자와 일반 한국어를 정확하게 발음한다.
- AI 자기인식 비트를 한 번만 사용해 반복 가능한 B급 코미디 문법을 만든다.
- 검은 박스 없이 모바일에서 읽기 쉬운 동기화 자막을 제공한다.
- 게시 전에 소상공인이 영상과 음성을 직접 승인하게 한다.
- TTS·이미지·자막 검증이 실패하면 저품질 대체본을 게시하지 않는다.

### 2.2 비목표

- 배경음악, 효과음, 음악·자막 전용 영상은 지원하지 않는다.
- 오발음, 고의적인 맞춤법 오류, 지역·장애·실존 인물 음성 모사는 사용하지 않는다.
- 자유 형식 LLM이 확인되지 않은 가격, 할인, 성능 주장을 만들게 하지 않는다.
- 첫 단계에서 음성 복제, 고객별 커스텀 보이스 학습, 다국어 TTS를 제공하지 않는다.
- 승인 없는 YouTube 자동 게시를 제공하지 않는다.

## 3. 카피와 코미디 규칙

한 영상은 원칙적으로 네 장면으로 구성한다.

1. 상품을 진지하게 소개한다.
2. AI 자기인식 비트를 한 번 사용한다.
3. 저장된 상품 정보에서 검증된 장점 하나를 말한다.
4. 정상적인 상품명과 CTA로 끝낸다.

AI 자기인식 비트는 영상당 정확히 한 번만 허용한다. 한 비트는 연속된 1~2개의 짧은
문장으로 구성하며 전체 발화 시간의 35%를 넘지 않는다. 문장은 승인된 템플릿과 저장된
상품 사실을 조합해 만든다. 자유 생성이 필요해져도 결과를 사실 검증한 뒤 사용하며,
초기 구현은 규칙 기반 문장 은행을 기본으로 한다.

전자레인지 예시:

```text
전자레인지입니다.
저는 식사를 하지 않습니다.
그래도 아침은 따뜻하게 먹는 편이 좋다고 학습했습니다.
출근 전에 확인해 보세요.
```

시간대 예시:

```text
저는 시간을 느끼지 못합니다.
하지만 지금이 출근 시간이라는 것은 압니다.
바쁜 아침을 간편하게 준비하세요.
```

다음 표현은 금지한다.

- 저장된 근거가 없는 가격·할인율·성능 수치
- AI가 실제 감정·의식·권한을 가진 것처럼 오해시키는 문장
- 특정 개인, 지역 억양, 장애 특성을 웃음 소재로 삼는 문장
- 두 번 이상 등장하거나 전체 발화 시간의 35%를 넘는 자기인식 비트

## 4. 장면과 이미지 설계

### 4.1 장면 구조

기본 길이는 12초이며 TTS 결과에 따라 10~15초 안에서 조정한다.

| 장면 | 목적 | 권장 길이 |
|---|---|---:|
| 1 | 상품 소개 | 2.0~2.8초 |
| 정적 | 코믹 호흡 | 0.4~0.8초 |
| 2 | AI 자기인식 | 2.0~2.8초 |
| 정적 | 코믹 호흡 | 0.4~0.8초 |
| 3 | 검증된 상품 장점 | 2.5~3.2초 |
| 4 | 상품명과 CTA | 2.5~3.2초 |

고정 장면 길이에 음성을 억지로 맞추지 않는다. TTS WAV 길이를 먼저 측정하고 각
장면에 선행·후행 정적을 더해 타임라인을 계산한다. 전체가 15초를 넘으면 음성을
가속하지 않고 대본을 줄여 다시 합성한다.

### 4.2 이미지 세트

기존 `Storyboard`는 하나의 `image_path`를 모든 장면에서 재사용한다. 새 설계는
장면별 이미지 경로와 해시를 가진 3~4개 `SceneImage`를 사용한다.

- 장면 1: 정면 영웅 이미지
- 장면 2: 생활 공간 또는 시간대 분위기 이미지
- 장면 3: 상품 장점을 보여주는 구도
- 장면 4: 여백이 충분한 CTA용 이미지

각 이미지는 기존 model server의 `fast_composite / 768 / 4-step` 경로를 재사용하고,
장면 목적별 프롬프트만 달리한다. 상품 원본은 동일하게 유지한다. 장면 생성 요청은
현재 GPU 잠금 정책에 따라 순차 처리하며, 일부 요청이 실패해 이미지가 3장 미만이면
한 이미지를 억지로 반복하지 않고 작업을 실패 처리한다.

이미지 요청·응답 해시를 `source_fingerprint`에 포함해 원본이 바뀐 뒤 오래된 영상을
승인하지 못하게 한다.

## 5. TTS 후보와 선택 게이트

### 5.1 1차 후보: MeloTTS-Korean

1차 평가 후보는 MyShell의 `MeloTTS-Korean`이다.

- 공식 MeloTTS 저장소는 한국어 지원과 CPU 실시간 추론을 명시한다.
- 공식 저장소의 라이브러리 라이선스는 MIT이며 상업·비상업 이용 가능하다고 명시한다.
- 공식 Hugging Face 모델 페이지는 한국어 모델을 MIT로 표시한다.
- 모델 저장소 크기는 약 208MB이므로 Git에 넣지 않고 외부 모델 캐시에 저장한다.

참고:

- <https://github.com/myshell-ai/MeloTTS>
- <https://github.com/myshell-ai/MeloTTS/blob/main/LICENSE>
- <https://huggingface.co/myshell-ai/MeloTTS-Korean/tree/main>

MIT 표시는 상업 이용 후보가 될 수 있다는 근거이지 발음 정확도 보증이 아니다.
모델 다운로드 전 사용자 확인을 받고, 고정 revision과 SHA-256을 기록한다. 다음 발음
평가를 모두 통과한 뒤에만 운영 기본 엔진으로 채택한다.

- 일반 한국어 문장
- 브랜드명과 상품명
- 숫자, 가격, 시간, 단위와 영문 혼용
- 받침·연음이 많은 문장
- 출근·퇴근 러시아워 샘플 대본

### 5.2 비추천 후보

- `eSpeak NG`: 한국어와 WAV 출력을 지원하고 의도한 로봇 음색에 가깝지만 GPL-3.0
  계열이며, 현재 프로젝트에서 한국어 발음 정확도가 실측되지 않았다. 운영 대체
  엔진으로 자동 사용하지 않는다.
- `OpenVoice V2`: MIT와 한국어 지원을 명시하지만 음성 복제·스타일 제어 기능은 이번
  MVP에 과도하고, 참조 음성의 권리·동의 관리가 추가된다.

참고:

- <https://github.com/espeak-ng/espeak-ng>
- <https://github.com/espeak-ng/espeak-ng/blob/master/docs/languages.md>
- <https://huggingface.co/myshell-ai/OpenVoiceV2>

### 5.3 발음 보정과 음색

`PronunciationLexicon`은 원문 표기와 TTS용 읽기 표기를 분리한다.

```text
display_text: "ABC-1200"
spoken_text: "에이비씨 천이백"
```

자막에는 `display_text`, TTS에는 `spoken_text`를 사용한다. 상품 등록 또는 영상
미리보기 단계에서 소상공인이 브랜드명·상품명의 읽기 표기를 확인할 수 있어야 한다.

코믹한 음색은 오발음이나 노이즈·비트 크러시로 만들지 않는다. 한 개의 승인된 음성
프리셋에 제한적인 속도·피치 조정을 적용하고, 원문 단어의 명료도가 떨어지면 조정을
폐기한다. 정적은 TTS 모델에 맡기지 않고 별도 무음 구간으로 합성한다.

## 6. 자막과 화면 디자인

검은 배경 박스를 제거한다. 기본 자막은 다음 규칙을 따른다.

- 화면 하단 안전영역에 최대 두 줄
- 밝은 굵은 글자, 얇은 외곽선, 부드러운 그림자
- 문장당 핵심어 하나만 제한된 포인트 색상 적용
- 음성 문장 시작·종료와 동기화
- 상품 보호 영역과 겹치면 상단 안전영역으로 자동 이동
- CTA 장면에서만 브랜드 컬러와 제한적인 버튼형 장식 사용

음성 없이 보더라도 상품과 문장을 이해할 수 있어야 하지만, 자막 자체를 음악·자막
전용 영상으로 사용하는 대체 경로는 제공하지 않는다.

## 7. 컴포넌트와 책임

### 7.1 `ComicScriptBuilder`

- 상품 사실과 시간대를 입력받아 네 장면 대본을 만든다.
- AI 자기인식 비트가 정확히 한 번이고 허용 길이 이내인지 검증한다.
- 금지된 수치·할인·근거 없는 주장을 차단한다.

### 7.2 `SceneImageProvider`

- 장면 목적별 이미지 프롬프트를 만든다.
- model server를 순차 호출해 3~4개 이미지를 저장한다.
- 이미지 해시, 상품 보존 결과와 장면 목적을 반환한다.

### 7.3 `TTSProvider`

- `synthesize(spoken_text, output_path, voice_preset)` 인터페이스를 제공한다.
- 운영 구현은 발음 검증을 통과한 MeloTTS adapter로 제한한다.
- 테스트에서는 WAV fixture 또는 fake provider를 사용한다.

### 7.4 `PronunciationLexicon`

- 표시 문장과 발화 문장을 분리한다.
- 등록되지 않은 브랜드·상품명은 검토 필요 상태를 반환한다.

### 7.5 `ComicShortsRenderer`

- 장면 이미지, TTS WAV, 정적, 자막을 FFmpeg로 합성한다.
- 배경음악과 효과음 입력을 받지 않는다.
- ffprobe로 해상도·길이·코덱·오디오 스트림을 검증한다.

### 7.6 `VideoWorkflowService`

- 생성, 미리보기, 승인, 러시아워 노출, 선택적 YouTube 예약 상태를 관리한다.
- 발음·이미지·자막 검증 실패가 있으면 승인을 차단한다.

## 8. 데이터 흐름

```text
러시아워 ToneResult + 상품 사실
  -> ComicScriptBuilder
  -> PronunciationLexicon
  -> SceneImageProvider (3~4장)
  -> TTSProvider (문장별 WAV)
  -> 타임라인 계산 (발화 길이 + 정적)
  -> ComicShortsRenderer (이미지 + 자막 + TTS)
  -> ffprobe/해시 검증
  -> 소상공인 미리보기와 승인
      -> 러시아워 노출
      -> YouTube 예약 게시 (명시적 선택 시에만)
```

## 9. 스키마 변경 방향

PR #17은 아직 Draft이고 운영 데이터 마이그레이션 대상이 없으므로 음악 중심 필드를
유지하는 호환 계층을 만들지 않는다.

제거 대상:

- `music_key`
- `music_warning`
- `silent_publish_confirmed`
- 승인 요청의 `allow_silent`
- `MusicCatalog` 및 러시아워 렌더링의 `music_path`

추가 대상:

- `script_version`
- `tts_engine`
- `tts_voice_preset`
- `tts_audio_sha256`
- `pronunciation_review_required`
- `scene_image_sha256s`
- `caption_layout_version`

실제 WAV, MP4, 모델 가중치는 Git에 커밋하지 않는다.

## 10. 실패 처리와 승인 게이트

다음 중 하나라도 발생하면 `render_status=failed` 또는 `needs_review`로 처리하고 게시를
차단한다.

- 이미지가 3장 미만이거나 `product_preserved`가 실패함
- TTS 엔진·모델 해시가 승인된 값과 다름
- 상품명 또는 브랜드명의 발음 검토가 끝나지 않음
- 오디오가 없거나 문장과 WAV 수가 다름
- 전체 길이가 10~15초를 벗어남
- 자막이 안전영역을 침범하거나 두 줄 제한을 넘음
- ffprobe 결과가 1080×1920, H.264, AAC 조건과 다름
- 원본 이미지·상품 정보가 렌더 이후 변경됨

기존 음악·자막 영상이나 단일 이미지 영상으로 자동 폴백하지 않는다. 사용자는 실패
이유를 확인하고 대본·발음·이미지를 수정한 뒤 다시 생성한다.

## 11. 테스트와 검수

### 11.1 자동 테스트

- 자기인식 비트가 영상당 정확히 한 번이고 전체 발화 시간의 35% 이하인지 확인
- 상품 데이터에 없는 가격·할인·성능 수치가 대본에 없는지 확인
- `display_text`와 `spoken_text`가 올바르게 분리되는지 확인
- 등록되지 않은 고유명사가 승인 차단 상태를 만드는지 확인
- 이미지 3장 미만 및 상품 보존 실패 시 렌더 차단
- 문장별 WAV 길이로 장면 타임라인이 계산되는지 확인
- 검은 자막 박스와 음악 입력 경로가 제거됐는지 회귀 테스트
- 10~15초, 1080×1920, H.264/AAC 출력 검증
- 동시 요청 시 렌더 큐와 GPU 생성 직렬화가 유지되는지 확인
- 승인 전 러시아워 노출 및 YouTube 게시 차단

### 11.2 사람 검수

최소 두 개의 실제 상품과 `commute_am`, `commute_pm` 결과를 사용한다.

- 상품명, 브랜드명, 숫자와 문장 발음이 정확한가
- 음색은 인공적이지만 비하·모사 없이 명료한가
- 정적이 오류가 아니라 코믹 타이밍으로 느껴지는가
- 자기인식 비트가 상품을 가리거나 광고의 중심이 되지 않는가
- 이미지 3~4장이 서로 구분되면서 상품을 보존하는가
- 자막이 모바일에서 읽히고 상품을 가리지 않는가
- 마지막 CTA가 정상적인 광고로 기능하는가

박재철(UI·UX)은 화면·자막·코믹 타이밍을 검수하고, 안은남(PM)은 기능 범위와 최종
승인 기준을 조율한다. 성치용은 모델·쇼츠 연동과 코드 수정, 김재헌A는 model server
API와 L4 생성 경로를 담당한다.

## 12. 운영과 비용

- TTS는 backend CPU 프로세스 또는 별도 CPU worker에서 실행해 L4 모델 서버와
  분리한다.
- MeloTTS 모델은 약 208MB이며 Git 외부 캐시에 revision·SHA-256과 함께 보관한다.
- 이미지 3~4장은 기존 단일 이미지보다 model server 요청 수가 늘지만 새로운 영상
  생성 모델은 추가하지 않는다.
- 규칙 기반 카피와 로컬 TTS에는 LLM 토큰 비용이 없다.
- 실제 운영 전 TTS 생성시간, CPU·RAM, 동시성, 모델 로딩시간을 별도로 벤치마크한다.

## 13. 완료 기준

- 러시아워 쇼츠 경로에 음악·효과음·검은 자막 박스가 없다.
- 고품질 상품 이미지 3~4장과 문장별 자막이 사용된다.
- 승인된 한국어 발음 평가 문장을 모두 통과한다.
- AI 자기인식 비트가 영상당 정확히 한 번이며 전체 발화 시간의 35% 이하이다.
- 두 실제 상품의 출근·퇴근 샘플이 10~15초 규격을 통과한다.
- UI·UX와 PM 검수가 완료되기 전 게시할 수 없다.
- 전체 자동 테스트와 FFmpeg/ffprobe 검증이 통과한다.
- 모델, 음성, MP4, 자격 증명 파일이 Git에 포함되지 않는다.
