# 러시아워 쇼츠 15초 시간 예산 디자인

## 1. 문제와 근거

VM E2E 작업 `video_906b946fcef1`은 장면 이미지와 MeloTTS 합성까지 성공했지만
FFmpeg 렌더 직전 길이 검증에서 실패했다. 실제 WAV 길이는 각각 4.186초,
6.016초, 5.633초, 6.527초였고, 발화 합계 22.362초에 고정 무음 1.600초가
더해져 예상 길이가 23.962초였다. WAV 프레임 수를 샘플레이트로 나누는 측정은
정상이므로 단위 오류가 아니라 대본의 발화량이 15초 영상 계약보다 긴 것이 원인이다.

## 2. 선택한 접근

`deadpan-ai-v3` 대본을 기존보다 약 40~45% 짧게 만들고, 렌더러는 각 장면의
`duration_sec`를 실제 최소 길이로 사용한다. 발화가 짧으면 장면 목표 길이까지 뒤쪽
무음을 늘리고, 발화가 길면 자연스러운 속도를 유지한 채 발화와 최소 무음 길이를
사용한다.

다음 대안은 사용하지 않는다.

- 1.6배 이상 강제 배속: 현재 23.962초를 15초에 맞출 수 있지만 한국어 발음과
  무표정 코믹 타이밍이 훼손된다.
- 15초 제한 완화: 러시아워 쇼츠의 10~15초 계약과 기존 검증을 깨뜨린다.
- 초과 시 TTS 전체 재생성: VM에서 합성 시간이 길어 실패 요청의 처리 비용을
  두 배로 만들 수 있다.

## 3. 대본 계약

네 장면과 사실성 계약은 유지한다. 상품명과 첫 번째 저장 소구점만 사용하며 가격,
할인, 성능을 만들지 않는다. 표시 문장과 발화 문장은 발음 사전을 거쳐 분리한다.

대표 문장은 다음처럼 짧게 만든다.

1. `INTRO`: `휴대용 선풍기, 나왔습니다.`
2. `SELF_AWARE`: `광고입니다. 저도 압니다.`
3. `BENEFIT`: `USB-C 충전, 됩니다.`
4. `CTA`: `보세요. 저는 안 쉽니다.`

시간대별 두 개 템플릿의 결정적 SHA-256 선택은 유지한다. 대본 변경을 저장된
지문과 운영 로그에서 구분할 수 있도록 `SCRIPT_VERSION`을 `deadpan-ai-v3`로 올린다.
MeloTTS 음성 프리셋과 속도 `0.94`는 변경하지 않는다.

## 4. 단일 시간 계산

각 장면의 최소 무음은 기존대로 일반 장면 앞뒤 0.1초, 자기인식 장면 앞뒤
0.5초다. 장면 시간은 다음 한 함수에서 계산하고 사전 검증과 FFmpeg 입력이 같은
결과를 사용한다.

```text
minimum = speech + 2 * minimum_silence
segment = max(storyboard_target, minimum)
pre = minimum_silence
post = segment - speech - pre
```

따라서 짧은 TTS는 스토리보드 목표 합계 11초까지 자연스럽게 패딩되고, 긴 TTS는
잘리지 않는다. 최종 예상 길이가 9.95~15.05초 밖이면 FFmpeg 전에 실패한다.

## 5. 진단과 검증

길이 실패 메시지에는 예상 합계, 발화 합계, 무음 합계, 장면별 발화 길이와 허용
범위를 포함한다. PR #25의 `ffmpeg_render` 단계 traceback이 이 메시지를 VM 터미널에
남기므로 재현용 별도 스크립트가 필요하지 않다.

자동 검증은 다음을 확인한다.

- 현재 실측값이 정확히 `23.962s`로 재현되고 FFmpeg 전에 차단된다.
- 장면 목표 길이 패딩과 실제 FFmpeg 렌더가 같은 계산을 사용한다.
- 새 대본이 결정적이며 네 장면, 첫 소구점, 발음 사전 계약을 유지한다.
- 집중 테스트, 전체 pytest, Ruff, compileall, `git diff --check`가 통과한다.

실제 MeloTTS 길이와 자연스러움은 모델 파일이 있는 L4 VM에서 새 E2E 작업으로
확인한다. 자동 테스트 통과만으로 실제 15초 성공을 확정하지 않는다.
