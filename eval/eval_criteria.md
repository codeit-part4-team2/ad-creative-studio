# 평가 기준

회의록 화면⑤와 05 기능 스코프 기준. 담당: 안은남(R1, 하네스 설계) + 유수빈(R2, 보존율 측정 구현).
R4+R5는 `docs/api_contract.md`의 `product_preserved` 필드를 그대로 이 하네스에 넘겨준다.

## 1순위 — 제품 보존율 (Product Preservation)

톤이 아무리 예뻐도 제품이 원본과 달라지면 실격 (화면⑤). 다른 지표보다 먼저 측정한다.

| 항목 | 측정 방법 |
|---|---|
| Product Preservation | 원본 제품 crop vs 생성 이미지 해당 영역 — masked SSIM 또는 CLIP image similarity |

## 2순위 — 생성 품질/속도

| 항목 | 측정 방법 |
|---|---|
| 정확도와 적합도 | 톤·시간대 프롬프트가 실제 생성 결과에 반영됐는가 (사람 평가, 5점 척도) |
| 일관성과 안정성 | 같은 조건 반복 생성 시 톤/스타일 일관성 (사람 평가) |
| 응답 속도와 부하 처리 | `GET /api/v1/jobs/{id}`의 `estimated_seconds` vs 실측, VRAM 사용량 (R3 로깅) |

## 3순위 — 서비스 완성도

| 항목 | 측정 방법 |
|---|---|
| 유저 중심 인터페이스 | 외부인 1~2명 사용자 테스트 (Sprint2, R1 진행) |
| 제어 가능성 | 문구 재수정(PATCH `/copy`)이 이미지 재생성 없이 정상 동작하는가 |

## 골든 데이터셋 (예정)

- 소형가전 카테고리 3~4개(주방/생활가전 등) × 제품 2~3개
- 톤 4종 × 시간대 6종 조합에 대한 기대 결과(참고 이미지·문구 방향) 정의
- 위치: `eval/golden_dataset/` (Sprint1에서 채움, 지금은 폴더만 확보)

## 자동 지표 vs 사람 평가

- 자동: Product Preservation, Generation Time
- 사람 평가: 정확도/적합도, 일관성, UI, 완성도, 제어 가능성 — 표본이 작을 수밖에 없음을 보고서에 명시
